## FLEX Disk Wrangler 1.0.0

The first full release of FLEX Disk Wrangler, a program for disc images of **TSC FLEX**, the disc operating system of
6800 (FLEX 2) and 6809 (FLEX 9) computers, and of **UniFLEX**, TSC's multi-user system for the same 6809 machines. It
is the third Disk Wrangler, beside Acorn Disk Wrangler and CP/M Disk Wrangler, built on the same DiskWranglerCore
library (version 1.6.0). It follows eight release candidates; thank you to everyone who tried them.

### Changes since release candidate 8
- The manual page (`man flexdw`) is easier to read: no stretched spaces between words, a comment above every
  example, and it says what the `~` in front of a FLEX file's size means (FLEX keeps whole sectors, so the true
  length isn't known).
- It moves to the DiskWranglerCore library version 1.6.0 (from 1.5.0). Nothing changes in how the program reads or
  writes discs.

### What it does
- **Reads** raw FLEX images (`.dsk`), and FLEX discs in ImageDisk, DSK and TeleDisk files, in whatever geometry the
  disc's System Information Record gives (with a double-density disc's single-density track 0 padded or stored at
  its own size): lists the files, views them (FLEX text with its space compression expanded, or hex), and copies
  them out by Extract, drag and drop or Copy. Files come out exactly as stored (CR line ends, space compression
  kept), so out and back in gives the same file; a random-access file comes out without its sector map.
- **Writes** them: add files (Add files, drop, Paste), rename, protect (write, delete, read, catalogue) and delete
  files, and change the volume name and number. Discs held in ImageDisk and DSK files are saved back into the same
  kind of file, every track keeping its density and sector numbers; Save As writes ImageDisk, DSK or raw.
- **Changes are made the way FLEX makes them.** Where a new file's entry goes, which sectors it takes, how the
  directory grows, what deleting leaves, a random-access file's sector map and the System Information Record after
  each change were read from FLEX itself (FLEX 2.0 and three FLEX 9s), and checked against FLEX 2.0 and FLEX 9.1
  running in emulators. As in FLEX, a protected file can't be deleted, renamed or replaced (take the protection off
  in Properties first), and an empty file can't be stored.
- **UniFLEX discs** (8-inch floppies and 15 MB Winchesters) open as a tree of folders, with each file's access,
  owner, links, size, time and file descriptor node, and are **changed the way UniFLEX's own kernel changes them**
  (read from TSC's sources, then checked against UniFLEX 3.14 running in an emulator, byte for byte): add files and
  folders, New directory, rename and move files and folders (dragging within the tree moves them), Properties (name,
  access bits, owner), Delete, and the volume's pack name, file system name and number. A UniFLEX disc with errors
  opens read-only with the faults named.
- **New disc images** in the shapes of real FLEX discs and TSC's formats (5.25-inch: 35 or 40 tracks of 10, 18, 20 or
  36 sectors; 8-inch: 77 tracks of 15, 26, 30 or 52), laid out as FLEX's NEWDISK lays a disc out, and in TSC's four
  8-inch UniFLEX formats; as raw, ImageDisk or DSK files.
- **The boot loader.** FLEX's boot loader is TSC's own code, so the program carries none: a new disc works under FLEX
  but doesn't start it. To make a disc that starts FLEX, copy the loader from a FLEX system disc you have (New disc
  image, or Tools > Copy boot loader from), put FLEX.SYS on the disc and link the loader to it (Tools > Link boot
  loader to file), as FLEX's LINK command does.
- **Checks** a disc's directory, file chains and free chain (Tools > Check disc); on UniFLEX, the whole file system.
  A disc with errors, or whose image file isn't the size its System Information Record gives, opens read-only. Every
  save is checked, and the saved copy is read back and checked before it replaces the original (with a `.bak` copy if
  you want one).
- **OS-9 discs** are recognised and named, not opened.
- **Exchanges files** with the other Disk Wranglers and other programs by drag and drop and Copy / Paste (the
  retro-files format): a file from another FLEX disc keeps its protection and date, a random-access file becomes
  random-access again with a new map, and a UniFLEX file keeps its access and owner.
- **Command-line program `flexdw`**, installed beside the program (Windows: beside the `.exe`; macOS: inside the app,
  `Contents/MacOS/flexdw`; Linux: `/usr/bin/flexdw` from the `.deb`, or the AppImage started under the name `flexdw`):
  info, check, ls, get, put, rm, mkdir, mv, attr, title, copy, convert, new and script, with `--json`, exit codes and
  `--dry-run`, as the other Disk Wranglers' console programs; `man flexdw` (Linux `.deb`) describes them.

The UniFLEX work rests on the people who kept UniFLEX alive: the **FLEX UniFLEX User Group** and **The Missing 6809
UniFLEX Archive**, which keep its discs, sources and manuals.

### Known limits
- TeleDisk files can't be saved as TeleDisk (Save As another kind).
- A DSK file has no way to say a track is single density: a single-density track 0 in a DSK file reads back as
  double density (the data is the same). Use ImageDisk to keep it.
- A new UniFLEX disc has no swap space and no bootstrap: it holds files but doesn't start UniFLEX.
- `flexdw` can't copy a boot loader or set the volume number (the window can; `flexdw title` sets the volume name).
- Deleted files can't be recovered yet.
- None of the builds is signed: Windows and macOS warn the first time you start it.

### Building from source
The shared code is the DiskWranglerCore library (version 1.6.0), a git submodule in `core/`. Clone with
`git clone --recurse-submodules`, or run `git submodule update --init` after cloning. GitHub's "Download ZIP" and
"Source code" archives leave `core/` empty; use the complete source archive attached to this release.

### Downloads
Windows installer and zip, macOS disk image, Linux AppImage and .deb, each for Qt 6, with `flexdw` in each (and its
manual page in the .deb); and the complete source (`...-source.tar.gz`, with `core/`).
