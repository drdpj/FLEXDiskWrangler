## FLEX Disk Wrangler 1.0.0, release candidate 8

### Changes since release candidate 7
- **A manual page for `flexdw`.** The Linux `.deb` installs it, so `man flexdw` describes every command and option,
  with examples. `flexdw COMMAND --help` now lists that command's options.
- It moves to the DiskWranglerCore library version 1.5.0 (from 1.4.2). Nothing changes in how the program reads or
  writes discs.

### Changes in release candidate 7 (since release candidate 6)
- It moves to the DiskWranglerCore library version 1.4.1 (from 1.3.0). Nothing changes in how the program reads or
  writes discs.
- The README gains the sections the other Disk Wranglers have: settings and carrying the program with you, drag and
  drop between disc tools, where `flexdw` is installed, known limits, and building from source.

### Changes in release candidate 6 (since release candidate 5)
- **Fixed: dragging a folder onto another folder of the same UniFLEX disc copied it into itself.** A drag within the
  tree now moves the files and folders into the folder they are dropped on (a moved folder's `..` is rewritten as
  before, so the disc stays as UniFLEX expects). A name the folder already has is refused rather than replaced, and a
  folder can't go into itself. Dropped below the rows, they go to the top of the disc.
- While dragging, the folder the drop will land in is highlighted (a file's own folder when over a file).
- Files dropped from another program go to the folder they are dropped on, not to the one selected.

### Changes in release candidate 5 (since release candidate 4)
- **ImageDisk, DSK and TeleDisk files.** FLEX and UniFLEX discs now open from ImageDisk (`.imd`), DSK and extended
  DSK files, including a double-density disc's single-density track 0. They are changed and saved back into the same
  kind of file, every track keeping its density and sector numbers. TeleDisk (`.td0`) files open read-only; Save As
  makes a copy that can be changed.
- **New disc image as ImageDisk or DSK.** Choose ImageDisk or DSK in the file dialog to get the disc itself: its
  sides, density, and the single-density track 0 TSC's format has. `flexdw new --container=imd` (or `edsk`, or `dsk`
  where every track is the same) does the same.
- **Save As** a disc held in an ImageDisk, DSK or TeleDisk file as ImageDisk, DSK or raw; `flexdw convert` does the
  same. A raw image is saved as raw only, because it doesn't say how its sectors lay on the disc.
- Disc information says what kind of file the disc is in.
- Fixed: `flexdw info` called a healthy UniFLEX disc "read-only" though it could be changed.

Every sample disc was put into ImageDisk and DSK files as it lay on its real disc, and each reads, and changes,
exactly as its raw image does; files made by HxC Floppy Emulator and SAMdisk read the same, and SAMdisk reads back
the files the program has changed.

### Changes in release candidate 4 (since release candidate 3)
- **UniFLEX discs.** UniFLEX is TSC's multi-user, Unix-like system for the same 6809 machines. Raw UniFLEX images
  (8-inch floppies and 15 MB Winchesters) now open as a tree of folders, with each file's access (`rwxr-x`), owner,
  links, size, time and file descriptor node. View, Extract, drag out and Copy work as for FLEX, and Tools > Check disc
  checks the whole file system.
- **Changing UniFLEX discs, the way UniFLEX does.** Add files and folders (into the folder selected), New directory
  (F7), rename and move files and folders, Properties (name, access bits, owner), Delete (a folder with what is in
  it), Volume name (pack name, file system name and number), and New disc image in TSC's four 8-inch UniFLEX formats.
  Every change was read from TSC's own kernel and utility sources and then checked against UniFLEX 3.14 itself,
  running in an emulator: the disc it leaves is UniFLEX's, byte for byte. A new disc is identical to one UniFLEX's own
  formatter makes, but for the bootstrap (TSC's code, so the program leaves it out). UniFLEX's own tools can't move a
  folder; the program can, rewriting the folder's `..` with the kernel's own steps, so the disc stays as UniFLEX
  expects.
- A file brought onto a UniFLEX disc gets the time it is written, as UniFLEX's `copy` gives it, and keeps the access
  and owner it brings from another UniFLEX disc (one that brings none gets `rw-rw-`, as UniFLEX's shell gives a new
  file). A UniFLEX disc with errors opens read-only with the faults named: several surviving images were copied from
  running systems and aren't consistent.
- `flexdw` does all of this on UniFLEX discs too (`mkdir` as well; `new --format=uniflex-ds-dd` and the others;
  `new --list --json` gives each shape's `fs`).

The UniFLEX work rests on the people who kept UniFLEX alive: the **FLEX UniFLEX User Group** and **The Missing 6809
UniFLEX Archive**, which keep its discs, sources and manuals.

### Changes in release candidate 3 (since release candidate 2)
- **Double-density discs with a single-density track 0.** On a double-density disc, FLEX's track 0 is single density
  and has fewer sectors than the other tracks (TSC's *6809 FLEX Adaptation Guide*, Appendix B). An image that stores
  that shorter track 0 at its own size is now read and written; before, its files were read from the wrong places.
  Images that pad track 0 to the full track were already read, and still are.
- **More shapes for new disc images**, TSC's own formats: 5.25-inch 35 x 20 (double-sided, single density) and 8-inch
  77 x 26, 77 x 30 and 77 x 52 (single- and double-sided, single and double density). A new double-density disc gets
  a single-density track 0 as FLEX's NEWDISK makes one (the directory ends at its last sector), padded to the full
  track in the image so that emulators open it. The 35 x 18 shape now does the same (track 0 of 10 sectors, like the
  real disc it was taken from); rc.2 gave it a directory over the whole of track 0.
- Disc information and the status bar say when track 0 is stored short; `flexdw info --json` gives `track0Stored` and
  `flexdw new --list --json` each shape's `track0Sectors`.

(Release candidate 1 was never published: a fault in the tests, not the program, stopped its build.)

The first release of FLEX Disk Wrangler, a program for disc images of **TSC FLEX**, the disc operating system of 6800
(FLEX 2) and 6809 (FLEX 9) computers. It is the third Disk Wrangler, beside Acorn Disk Wrangler and CP/M Disk
Wrangler, built on the same DiskWranglerCore library (version 1.5.0).

This is a **release candidate**: please try it on copies of your discs, and say how the discs it has changed behave
under real FLEX or UniFLEX (an emulator or a real machine). That is the one thing the tests can't show.

### What it does
- **Reads** raw FLEX images (`.dsk`), and FLEX discs in ImageDisk, DSK and TeleDisk files, in whatever geometry the
  disc's System Information Record gives (with a double-density disc's single-density track 0 padded or stored at
  its own size): lists the files, views them (FLEX text with its space compression expanded, or hex), and copies
  them out by Extract, drag and drop or Copy. Files come out exactly as stored (CR line ends, space compression
  kept), so out and back in gives the same file; a random-access file comes out without its sector map.
- **Writes** them: add files (Add files, drop, Paste), rename, protect (write, delete, read, catalogue) and delete
  files, and change the volume name and number.
- **Changes are made the way FLEX makes them.** Where a new file's entry goes, which sectors it takes, how the
  directory grows, what deleting leaves, a random-access file's sector map and the System Information Record after
  each change were read from FLEX itself (FLEX 2.0 and three FLEX 9s). As in FLEX, a protected file can't be deleted,
  renamed or replaced (take the protection off in Properties first), and an empty file can't be stored.
- **New disc images** in the shapes of real FLEX discs and TSC's formats (5.25-inch: 35 or 40 tracks of 10, 18, 20 or
  36 sectors; 8-inch: 77 tracks of 15, 26, 30 or 52), laid out as FLEX's NEWDISK lays a disc out.
- **The boot loader.** FLEX's boot loader is TSC's own code, so the program carries none: a new disc works under FLEX
  but doesn't start it. To make a disc that starts FLEX, copy the loader from a FLEX system disc you have (New disc
  image, or Tools > Copy boot loader from), put FLEX.SYS on the disc and link the loader to it (Tools > Link boot
  loader to file), as FLEX's LINK command does.
- **Checks** a disc's directory, file chains and free chain (Tools > Check disc). A disc with errors, or whose image
  file isn't the size its System Information Record gives, opens read-only. Every save is checked, and the saved copy
  is read back and checked before it replaces the original (with a `.bak` copy if you want one).
- **UniFLEX discs** are read and changed as UniFLEX changes them (above). **OS-9 discs** are recognised and named, not
  opened.
- **Exchanges files** with the other Disk Wranglers and other programs by drag and drop and Copy / Paste (the
  retro-files format): a file from another FLEX disc keeps its protection and date, and a random-access file becomes
  random-access again with a new map.
- **Command-line program `flexdw`**, installed beside the program (Windows: beside the `.exe`; macOS: inside the app,
  `Contents/MacOS/flexdw`; Linux: `/usr/bin/flexdw` from the `.deb`, or the AppImage started under the name `flexdw`):
  info, check, ls, get, put, rm, mv, attr, title, copy and new (`flexdw new --list` for the shapes), with `--json`,
  exit codes and `--dry-run`, as the other Disk Wranglers' console programs; `man flexdw` (Linux `.deb`) describes them.

### Known limits
- TeleDisk files can't be saved as TeleDisk (Save As another kind).
- A DSK file has no way to say a track is single density: a single-density track 0 in a DSK file reads back as
  double density (the data is the same). Use ImageDisk to keep it.
- A new UniFLEX disc has no swap space and no bootstrap: it holds files but doesn't start UniFLEX.
- `flexdw` can't copy a boot loader or set the volume number (the window can; `flexdw title` sets the volume name).
- Deleted files can't be recovered yet.
- None of the builds is signed: Windows and macOS warn the first time you start it.

### Building from source
The shared code is the DiskWranglerCore library (version 1.5.0), a git submodule in `core/`. Clone with
`git clone --recurse-submodules`, or run `git submodule update --init` after cloning. GitHub's "Download ZIP" and
"Source code" archives leave `core/` empty; use the complete source archive attached to this release.
